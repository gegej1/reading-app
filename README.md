# 底色（Dise）

「底色」是个人「决策底色」知识库的 Mac App 与网页版。同一套前端有两种形态：

- **Mac App**：基于 Tauri 2（Rust）的桌面应用，直接读写本机的知识库 Git 仓库。
- **网页版**：静态 PWA，计划部署到 GitHub Pages（<https://gegej1.github.io/reading-app/>），通过 GitHub REST API 访问知识库（后续里程碑）。目前网页版显示虚构的演示数据。

> 本仓库公开，只放代码；个人内容在私有知识库里，令牌只存在设备上。测试和演示用的都是虚构数据（`src/domain/__fixtures__/`）。

## 现在能做什么

五个界面：**今日**（待办计数、最近一次入库、今日一条底色、入库 ▶ / 落裁决 ▶）· **底色**（人物志式的条目卡片，可以盖章确认；AI 起草的草稿另有样子）· **裁决**（待裁决队列和待抽查清单：回答、认可、不认可）· **知识**（书、判例、概念、人物与公司、体系，带全文搜索和反向链接）· **原料**（逐字原文）。桌面 App 的左侧栏底部还有运行记录和**设置**。

**记一笔**：随手记下一句话，直接进知识库的收件箱（`inbox/`），等下次入库时整理。桌面 App 里是一张浮在所有窗口之上的小纸条（全局快捷键 ⌃⌥N、菜单栏图标或今日页的「记一笔」），网页版和演示里是页面上的对话框。⌘↩（Windows 上 Ctrl+↩）记下，↩ 换行，Esc 收起但保留草稿；用输入法打字或听写时，候选还没上屏的按键不会触发保存。草稿每改一次都存在本地，App 崩溃也不会丢。

**同步**（桌面 App）：知识库和它的 Git 远端自动保持一致，左侧栏底部显示状态（已同步 / ↑N 待推送 / ↓N 待拉取 / 离线 / 需要处理）。

**回答和抽查**（桌面 App、网页版和演示）：待裁决的问题页下面有一张回答纸条（和记一笔一样：⌘↩ 交上，输入法和听写照常，每个问题各存一份草稿），交上的回答进 `inbox/裁决/`，等下次落裁决整理；一个问题可以回答不止一次，问题上会标「已回答，待落裁决」。入库报告的待抽查清单（裁决台的「待抽查」和报告页）可以直接勾选认可，也可以点「不认可」写下理由，那一条会标「已驳回，待落裁决」。

**入库和落裁决**（桌面 App）：今日的「入库 ▶」（收件箱有随手记时）和裁决台的「落裁决 ▶」（有回答时）先打开一张确认单，写明任务、队列里有几条、引擎、模型（没设置时用引擎自己的默认）、每次的花费上限和「按用量计费，这次最多花 $X」，你点开始才运行。AI 引擎（Claude Code 或 Codex）按知识库的 `AGENTS.md` 整理收件箱或裁决，只改文件；运行面板逐行显示它读、写、改、查找了哪个文件，说了什么，哪些操作被拒绝，以及用时和花费，随时可以取消；关掉面板运行照常，左侧栏会一直显示进度。App 用一套固定的检查核对结果，通过了才删掉处理过的队列文件、提交并同步；没通过时面板列出每个问题和改动前后的逐行对照，由你选择丢弃（可找回）、仍然提交（要再确认一次）或手动改好后重新检查。主窗口不在前面时，运行结束会发一条系统通知，点一下就打开结果。命令行也能发起，详见下文「入库和落裁决」。网页版和演示里这两个按钮写着「只能在 Mac 上运行」。

App 只会以这几种方式写入知识库：

- 给底色条目加或去掉标题末尾的 ✅（提交说明如 `底色：确认 D05`），只提交那一个文件。确认 AI 起草的草稿时，同一行里去掉「（草稿，待你确认）」再加 ✅；取消确认只去掉 ✅，不会把草稿标记加回去；
- 勾选或取消勾选入库报告「待你抽查」清单里的一条（提交说明如 `抽查：认可 I-12（2026-10-12-入库报告）`），只改那一行；
- 记一笔：在 `inbox/` 新建 `YYYY-MM-DDTHH-mm-ss-<来源>.md`（来源为 `mac`、`iphone` 或 `web`），YAML 里写 `来源` 和带时区的 `时间`，空一行后是逐字原文（只把 CRLF 换成 LF，结尾留一个换行）；提交说明 `收件箱：记一笔（mac）`。同一秒里的第二条用 `-2`、`-3` 后缀，绝不覆盖已有文件；只提交那一个文件；
- 回答和驳回：在 `inbox/裁决/` 新建 `Q-001-YYYY-MM-DDTHH-mm-ss-<来源>.md`（回答待裁决，YAML 写 `对象: Q-001`）或 `抽查-<报告名>-I-12-YYYY-MM-DDTHH-mm-ss-<来源>.md`（不认可一条抽查，`对象: 抽查 <报告名> I-12`），另有带时区的 `时间` 和 `来源`（`mac` 或 `web`），正文和记一笔一样逐字保存；提交说明 `收件箱：回答 Q-001（mac）`、`收件箱：驳回抽查 I-12（2026-10-12-入库报告，mac）`，同样绝不覆盖已有文件；
- 入库或落裁决的结果：检查通过后（或你明确要求保留时）一次提交检查认可的文件，并删掉内容已经逐字进了 `raw/` 的队列文件（提交说明如 `入库：3 条（Claude）`、`落裁决：2 份（Codex）`）；你要求丢弃时，把这次运行改过的文件还原；
- 同步时的 fast-forward / rebase / push（规则见下文「同步」）。

## 技术栈

Tauri 2 · Vite 6 · React 18 · TypeScript（strict）· Vitest · pnpm · react-router（HashRouter）· react-markdown + remark-gfm · yaml

## 开发命令

环境要求：Node 22+、pnpm 10、Rust 1.90+。macOS 上只需要 Xcode Command Line Tools。

```bash
pnpm install      # 安装依赖
pnpm dev          # 前端开发服务器（演示数据，http://localhost:1420）
pnpm dev:kb       # 前端开发服务器 + 只读读取本机知识库（http://127.0.0.1:1420）
pnpm tauri dev    # 启动桌面应用（开发模式）
pnpm build        # 构建桌面版前端到 dist/（Tauri 打包时使用）
pnpm build:web    # 构建网页版到 dist-web/（base 为 /reading-app/）
pnpm test         # 单元测试
pnpm test:kb      # 只跑真实知识库兼容性测试（仅本机；CI 里自动跳过）
pnpm typecheck    # TypeScript 类型检查
pnpm icon         # 由 scripts/build-icon.mjs 重画图标（只用简单图形）并生成 src-tauri/icons/
pnpm icon:tray    # 由 scripts/build-tray-icon.mjs 重画菜单栏图标（单色模板图，只用简单图形）
cargo test --manifest-path src-tauri/Cargo.toml   # Rust 测试
```

## 知识库在哪里

桌面 App 和 `pnpm dev:kb` 按这个顺序找知识库：

1. 环境变量 `DISE_KB_PATH`；
2. （仅桌面 App）`~/Library/Application Support/com.gegej1.dise/config.json` 里的 `kbPath`，例如 `{ "kbPath": "/Users/你/Documents/阅读" }`；
3. 默认 `~/Desktop/GHJProject/阅读`。

`pnpm dev:kb` 只读：中间件只提供 `GET /__kb/list` 和 `GET /__kb/read?path=`，只接受本机请求，并且只在开发服务器里存在，不会进入任何构建产物。

同一个 `config.json` 里还有 AI 运行的设置（见下文「入库和落裁决」），也可以用 `captureShortcut` 换掉记一笔的全局快捷键，写法如 `"Ctrl+Alt+K"`、`"Cmd+Shift+Space"`，必须带 ⌃、⌥ 或 ⌘ 之一。默认是 ⌃⌥N（⌘⇧N 已经是 Finder 的「新建文件夹」和 Chrome 的「新的无痕窗口」）。快捷键注册不上（被别的 App 占用，或者写法不对）时 App 照常运行，日志里写明原因，菜单栏和今日页也会提示。这些都可以在 App 的「设置」里改（见下文）。

想在一份知识库副本上试用 App、又不碰真正的设置时，可以用环境变量 `DISE_APP_DIR` 指定另一个文件夹放 `config.json` 和运行记录。

## 设置（桌面 App）

左侧栏最下面的「设置」：

- **AI 引擎**：Claude 或 Codex（显示在这台 Mac 上找到的程序）、模型（可以写别名，留空就跟随引擎自己的默认）、每次运行的花费上限（美元，只对 Claude 有效）、运行时限（分钟）。保存后下一次运行就用新的设置。
- **知识库**：现在的文件夹和同步到哪里（只显示远端的主机名，或者本机文件夹，不显示地址本身）。「更换…」打开选择文件夹的窗口；只有 git 仓库的根目录才能选，选好后 App 重新载入。运行进行中不能换。
- **记一笔的快捷键**：点「录新的快捷键」后按下组合键。macOS 自己的快捷键（如 ⌘Space、⌃Space、⌘⇧4）和只带一个修饰键、会挡住打字或 App 自己快捷键的组合会被拒绝并说明原因；新的快捷键立刻生效，注册不上（被别的 App 占用）时原来的照常可用。
- **开机时自动打开**：默认关闭，只有你打开它才会在登录时启动。
- 打开日志文件夹、运行记录文件夹，以及 App 的版本。

保存时 `config.json` 原子写入（先写临时文件再改名），不认识的键原样保留；`config.json` 不是有效的 JSON 时拒绝保存，免得丢掉里面的内容。网页版和演示没有设置。

## 桌面 App 的行为

- **窗口**：点关闭按钮只是把窗口藏起来，App 仍在运行；点 Dock 图标再显示；⌘Q 或菜单栏的「退出」退出。再次打开 App 会切回已经在运行的那一个，不会开第二个。
- **菜单栏图标**：一枚单色的印章（模板图，跟随浅色和深色菜单栏）。菜单：记一笔（显示快捷键）/ 打开底色 / 一行状态（收件箱 N 条 · 待裁决 M 项 · 同步状态）/ 立即同步 / 退出。Dock 图标保留。
- **记一笔窗口**：560×300 的无边框小窗口，出现在鼠标所在屏幕的上三分之一处，总在最前，不进 Dock。点到别的 App 时，纸条上没写字就自动收起，写了字就留着。记下或收起后，焦点回到打开它之前的那个 App。这个窗口只能在 `inbox/` 里新建文件，不能读、列出或改写知识库里的任何文件。
- **命令行**：`"/Applications/底色.app/Contents/MacOS/dise" --capture "要记下的话"` 把一条随手记交给正在运行的 App（没有在运行时会启动它，记下后留在菜单栏，不打开主窗口），和在纸条上记下完全一样，结果写进日志。`--sync` 立即同步一次。`--ingest` 发起入库，`--land-rulings` 发起落裁决，可以加 `--engine claude|codex` 和 `--model <名字>` 只在这一次换掉设置里的引擎和模型；每一步和最后的结果都写进日志。
- **外部链接**：http / https 链接用默认浏览器打开（网页版在新标签页打开）。
- **命令行环境**：从 Finder 启动的 App 拿不到 shell 配置里的环境变量，所以 App 启动时在后台跑一次登录 shell（`$SHELL -ilc`，最多 10 秒），记下 `PATH`、代理等变量，之后启动的 `git` 等子进程都用这份环境。失败时退回到固定的 `PATH`（Homebrew、`~/.npm-global/bin` 等）加系统代理设置（`scutil --proxy`）。
- **日志**：`~/Library/Logs/com.gegej1.dise/dise.log`（满 2 MB 轮换，保留 3 份旧文件）。记录每个命令的名称、路径、结果和耗时（逐个读取文件只在 debug 级别，每次载入只留一行汇总），每次同步的结果，以及前端载入结果和未捕获的错误；不记录文件内容、随手记的文字、提交说明和环境变量的值。
- **一次只做一件事**：写入、记一笔和同步共用一把「知识库锁」。正在进行的操作结束前，写入最多等 45 秒、同步最多等 20 秒，然后明确报告「知识库正忙」，不会一直卡住。入库或落裁决进行中（以及结果等你处理时），写入和同步立刻得到「知识库正忙：正在入库」这样的回答，界面上盖章确认和勾选抽查也会停用并提示「正在入库，结束后再改」；记一笔照常工作，入库进行中回答和驳回也照常（`inbox/裁决/` 只在落裁决时要等），每条都单独提交，不会混进这次运行。
- **通知**：一次运行结束（或者没通过检查、等你处理）时如果主窗口不在最前面，App 发一条系统通知；点通知会打开主窗口和这次的结果。
- **事件**：后端向窗口发送 `kb-changed`（文件被写入、新建，同步时拉到了新内容，一次运行提交、丢弃了改动，或者在设置里换了知识库；主窗口据此重新载入）、`sync-status`（同步开始、结束，或写入后有新的待推送提交）、`run-status`（一次运行开始、进入下一阶段或结束）、`run-step`（运行中的每一步：读、写、改、查找哪个文件，AI 说的话，被拒绝的操作）和 `run-show`（点了运行的通知），以后的功能可以直接订阅。

## 同步

数据安全优先于新鲜。每次同步都拿着知识库锁，按这个顺序：

1. 不是仓库根目录、没有上游分支、HEAD 不在分支上，或者有没做完的 rebase / merge / cherry-pick / revert / bisect 时，直接跳过并说明原因。
2. `git fetch` 上游分支，最多 30 秒（另有低速限制）；失败就是「离线」，什么都不改。
3. 只落后：`git merge --ff-only`；如果 git 说会覆盖本地文件，就报告「需要处理」，什么都不改。
4. 分叉：有已跟踪文件改动（含已暂存）时跳过；否则先把 HEAD 存到 `refs/dise/backup/<秒数>`，再 `git rebase`；任何失败都 `git rebase --abort`，确认 HEAD 回到备份那一刻，报告冲突的文件。
5. 领先：`git push <远端> HEAD:<上游分支>`，最多 30 秒；如果远端在这期间有了新提交，再从第 2 步来一次。
6. 备份只保留最新 10 个。

绝不 force push、`reset --hard`、stash、clean、checkout 或 restore 文件，也不碰未跟踪的文件。所有 git 调用都用明确的参数、不经过 shell、使用登录 shell 的环境，并且设置 `GIT_TERMINAL_PROMPT=0`。

什么时候同步：启动后（登录 shell 环境准备好之后）一次；每次写入或记一笔后约 3 秒（连续写入只同步一次）；每 10 分钟一次；主窗口获得焦点时（最多每分钟一次）；菜单栏的「立即同步」、点左侧栏的同步状态，或命令行 `--sync`。同步拉到新内容后，主窗口会重新载入。

## 入库和落裁决

入库处理 `inbox/` 根目录下的随手记，落裁决处理 `inbox/裁决/` 下的回答。规则在知识库的 `AGENTS.md` 里（第二节入库、第三节落裁决、第九节由 App 发起的运行）；App 交给引擎的任务提示词在 `runners/`。

**一次运行的过程**：

1. 先同步一次，把别处记下的内容拿到本机。知识库不是仓库根目录、不在分支上、有改了没提交的已跟踪文件、没有 `AGENTS.md` 时不开始；队列是空的就根本不启动引擎（运行要花钱）。
2. 记下开始时的状态：当前提交、队列文件的内容、已经存在的未跟踪文件（它们属于你，什么时候都不会被提交、还原或删除）。
3. 引擎在知识库里工作，App 把每一步发给窗口，引擎的原始输出逐行存下来。可以随时停止；超过时限会被停止。
4. 引擎结束后（不管是做完、出错、被停止还是超时），App 列出这次运行改了哪些文件，交给主窗口里的检查程序（`src/domain/gate.ts`）核对：
   - 只改了 `raw/`、`wiki/`、`systems/`、`self/`、`reports/` 和 `index.md`、`log.md`；
   - `raw/` 里已有的文件只在末尾追加，没有删除或改名；
   - 每个队列文件的正文（去掉 YAML，统一换行，去掉首尾空白）都能在 `raw/` 里逐字找到；
   - 底色里带 ✅ 的条目一个字都没变，✅ 没有增加也没有减少；
   - 已有判例里"## 裁决"一节（你的原话）一个字都没变，已有判例也没有被删除或改名（新建判例不受限制）；
   - 没有新的断链；入库写了报告；落裁决把回答过的 Q 文件改成"已裁决"（驳回抽查时新建了 Q 文件）；
   - 引擎没有自己提交，也没有动过不在 Git 里的文件。
   最后那行 JSON 缺了或写错了只算提醒。Rust 一侧在提交前再查一遍其中最基本的两条（允许的目录、`raw/` 只增不改）。
5. 检查通过、引擎也正常结束：删掉内容已经进了 `raw/` 的队列文件，把检查认可的文件做成一次提交，然后同步。
6. 没通过：改动原样留在知识库里，同步不会推送它们，由你决定——**丢弃**（先把这次改过的每个文件复制到运行记录里，再把已跟踪的文件还原、删掉这次新建的文件；引擎自己做了提交的话，再加一个撤回的提交，不改写历史）、**保留**（明知没通过也提交，记在运行记录里），或者手动改好后**重新检查**。App 在这期间退出的话，下次启动时会接着等你处理。

**引擎**：

- **Claude Code** 以受限模式运行：`claude -p … --restricted`，只有读、写、改、查找文件的工具，没有命令执行，不加载你的用户设置、项目设置、hooks 和 MCP 服务器，有花费上限；读写只限于知识库文件夹。登录用的 `apiKeyHelper` 和 `ANTHROPIC_*`、`CLAUDE_CODE_*`、`API_TIMEOUT_MS` 设置从 `~/.claude/settings.json` 复制进一个只有你能读的临时文件（权限 0600），只在引擎运行期间存在，内容从不写进日志。没有可用的登录时会明确报告「没有可用的登录凭据」。
- **Codex** 在自己的 `workspace-write` 沙箱里运行，不需要确认，关掉你配置里的插件、apps、hooks、MCP 服务器等。Codex 只能通过命令读文件，所以任务提示词后面会加一段说明：允许只读命令和 apply_patch，git、删除、移动仍然不许。

**设置**（`config.json`，和 `kbPath` 放在一起，每次运行时重新读取；也可以在 App 的「设置」里改）：

| 键 | 含义 | 默认 |
|---|---|---|
| `engine` | `"claude"` 或 `"codex"` | `claude` |
| `model` | 模型名或别名（只用于 `engine` 指定的引擎） | 引擎自己的默认 |
| `budgetUsd` | 一次 Claude 运行的花费上限（美元） | `10` |
| `runTimeoutMinutes` | 超过这么多分钟就停止引擎 | `30` |
| `claudePath`、`codexPath` | 不用 `PATH` 上的 `claude` / `codex`，改用这个程序 | – |

**运行记录**：每次运行一个文件夹，在 `~/Library/Application Support/com.gegej1.dise/runs/<时间>-<任务>/`：`run.json`（谁发起的、引擎、模型、花费、轮数、检查结果、怎么结束的）、`events.jsonl`（引擎的原始输出）、`steps.jsonl`（运行面板显示过的每一步）、丢弃时的文件副本。保留最新 20 次（还在等你处理的不删）。运行面板的「运行记录」列出它们（时间、任务、引擎、模型、结果、花费或 token 数、用时），点开一次能看到它的每一步和检查结果。这些文件含有知识库内容，只留在本机。

## 路径安全

前端传来的路径都要过同一套规则（Rust：`src-tauri/src/kb/paths.rs`，TypeScript：`src/store/kbPath.ts`）：只接受知识库内的相对 POSIX 路径；拒绝绝对路径、`.` / `..` 段、`.git/` 和其他隐藏目录、非 `.md` 文件；符号链接解析后必须仍在知识库内。改写是原子的（临时文件 + 重命名），新建也是（临时文件 + 硬链接，名字已被占用时失败而不是覆盖；提交失败时撤回新文件）。提交只包含这一个文件。

## 目录结构

```text

  domain/       纯领域逻辑：frontmatter、双链、底色、判例、待裁决、入库报告、搜索、记一笔、运行结果的检查、loadKb
```
