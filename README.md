# 底色（Dise）

「底色」是个人「决策底色」知识库的 Mac App 与网页版。同一套前端有两种形态：

- **Mac App**：基于 Tauri 2（Rust）的桌面应用，直接读写本机的知识库 Git 仓库。
- **网页版**：静态 PWA，计划部署到 GitHub Pages（<https://gegej1.github.io/reading-app/>），通过 GitHub REST API 访问知识库（后续里程碑）。目前网页版显示虚构的演示数据。

> 本仓库公开，只放代码；个人内容在私有知识库里，令牌只存在设备上。测试和演示用的都是虚构数据（`src/domain/__fixtures__/`）。

## 现在能做什么

五个界面：**今日**（待办计数、最近一次入库、今日一条底色、入库 ▶ / 落裁决 ▶）· **底色**（人物志式的条目卡片，可以盖章确认；AI 起草的草稿另有样子）· **裁决**（待裁决队列和待抽查清单：回答、认可、不认可）· **知识**（书、判例、概念、人物与公司、体系，带全文搜索和反向链接）· **原料**（逐字原文）。桌面 App 的左侧栏底部还有**设置**（⚙），运行进行中或有新结果时还会显示运行的进度；今日页的「运行记录」列出以前的每一次运行。

**记一笔**：随手记下一句话，直接进知识库的收件箱（`inbox/`），等下次入库时整理。桌面 App 里是一张浮在所有窗口之上的小纸条（全局快捷键 ⌃⌥N、菜单栏图标或今日页的「记一笔」），网页版和演示里是页面上的对话框。⌘↩（Windows 上 Ctrl+↩）记下，↩ 换行，Esc 收起但保留草稿；用输入法打字或听写时，候选还没上屏的按键不会触发保存。草稿每改一次都存在本地，App 崩溃也不会丢。

**同步**（桌面 App）：知识库和它的 Git 远端自动保持一致，左侧栏底部显示状态（已同步 / ↑N 待推送 / ↓N 待拉取 / 离线 / 需要处理）。

**回答和抽查**（桌面 App、网页版和演示）：待裁决的问题页下面有一张回答纸条（和记一笔一样：⌘↩ 交上，输入法和听写照常，每个问题各存一份草稿），交上的回答进 `inbox/裁决/`，等下次落裁决整理；一个问题可以回答不止一次，问题上会标「已回答，待落裁决」。入库报告的待抽查清单（裁决台的「待抽查」和报告页）可以直接勾选认可，也可以点「不认可」写下理由，那一条会标「已驳回，待落裁决」。

**iPhone**（桌面 App）：手机上不用 VPN、不用 GitHub，也不用装别的 App，只用自带的「快捷指令」和「文件」，通过 iCloud 云盘和 Mac 互通：手机上记的一笔和对待裁决的回答由 Mac 收进知识库，Mac 把「底色层」（底色、判例、待裁决、待抽查、最近一次入库）做成手机页面放进 iCloud。原料、知识页、体系、收件箱和日志不会离开 Mac。详见下文「iPhone」。

**入库和落裁决**（桌面 App）：今日的「入库 ▶」（收件箱有随手记时）和裁决台的「落裁决 ▶」（有回答时）先打开一张确认单，写明任务、队列里有几条、引擎、模型（没设置时用引擎自己的默认）、每次的花费上限和「按用量计费，这次最多花 $X」，你点开始才运行。AI 引擎（Claude Code 或 Codex）按知识库的 `AGENTS.md` 整理收件箱或裁决，只改文件；运行面板逐行显示它读、写、改、查找了哪个文件，说了什么，哪些操作被拒绝，以及用时和花费，随时可以取消；关掉面板运行照常，左侧栏会一直显示进度。App 用一套固定的检查核对结果，通过了才删掉处理过的队列文件、提交并同步；没通过时面板列出每个问题和改动前后的逐行对照，由你选择丢弃（可找回）、仍然提交（要再确认一次）或手动改好后重新检查。主窗口不在前面时，运行结束会发一条系统通知，点一下就打开结果。命令行也能发起，详见下文「入库和落裁决」。网页版和演示里这两个按钮写着「只能在 Mac 上运行」。

App 只会以这几种方式写入知识库：

- 给底色条目加或去掉标题末尾的 ✅（提交说明如 `底色：确认 D05`），只提交那一个文件。确认 AI 起草的草稿时，同一行里去掉「（草稿，待你确认）」再加 ✅；取消确认只去掉 ✅，不会把草稿标记加回去；
- 勾选或取消勾选入库报告「待你抽查」清单里的一条（提交说明如 `抽查：认可 I-12（2026-10-12-入库报告）`），只改那一行；
- 记一笔：在 `inbox/` 新建 `YYYY-MM-DDTHH-mm-ss-<来源>.md`（来源为 `mac`、`iphone` 或 `web`），YAML 里写 `来源` 和带时区的 `时间`，空一行后是逐字原文（只把 CRLF 换成 LF，结尾留一个换行）；提交说明 `收件箱：记一笔（mac）`。同一秒里的第二条用 `-2`、`-3` 后缀，绝不覆盖已有文件；只提交那一个文件；
- 回答和驳回：在 `inbox/裁决/` 新建 `Q-001-YYYY-MM-DDTHH-mm-ss-<来源>.md`（回答待裁决，YAML 写 `对象: Q-001`）或 `抽查-<报告名>-I-12-YYYY-MM-DDTHH-mm-ss-<来源>.md`（不认可一条抽查，`对象: 抽查 <报告名> I-12`），另有带时区的 `时间` 和 `来源`（`mac`、`iphone` 或 `web`），正文和记一笔一样逐字保存；提交说明 `收件箱：回答 Q-001（mac）`、`收件箱：驳回抽查 I-12（2026-10-12-入库报告，mac）`，同样绝不覆盖已有文件；
- 入库或落裁决的结果：检查通过后（或你明确要求保留时）一次提交检查认可的文件，并删掉内容已经逐字进了 `raw/` 的队列文件（提交说明如 `入库：3 条（Claude）`、`落裁决：2 份（Codex）`）；你要求丢弃时，把这次运行改过的文件还原；
- 从 iPhone 收进来的随手记和回答：和上面的记一笔、回答完全一样（来源 `iphone`，提交说明 `收件箱：记一笔（iphone）`、`收件箱：回答 Q-001（iphone）`），每条单独提交（见下文「iPhone」）；
- 同步时的 fast-forward / rebase / push（规则见下文「同步」）。

## 技术栈

Tauri 2 · Vite 6 · React 18 · TypeScript（strict）· Vitest · pnpm · react-router（HashRouter）· react-markdown + remark-gfm · yaml

## 开发命令

环境要求：Node 22+、pnpm 10、Rust 1.90+。macOS 上只需要 Xcode Command Line Tools。

```bash
pnpm install      # 安装依赖
pnpm dev          # 前端开发服务器（演示数据，http://localhost:1420）
pnpm dev:kb       # 前端开发服务器 + 只读读取本机知识库（http://127.0.0.1:1420）
pnpm tauri dev    # 启动桌面应用（开发模式）
pnpm build        # 构建桌面版前端到 dist/（Tauri 打包时使用）
pnpm build:web    # 构建网页版到 dist-web/（base 为 /reading-app/）
pnpm test         # 单元测试
pnpm test:kb      # 只跑真实知识库兼容性测试（仅本机；CI 里自动跳过）
pnpm typecheck    # TypeScript 类型检查
pnpm icon         # 由 scripts/build-icon.mjs 重画图标（只用简单图形）并生成 src-tauri/icons/
pnpm icon:tray    # 由 scripts/build-tray-icon.mjs 重画菜单栏图标（单色模板图，只用简单图形）
pnpm shortcuts    # 由 scripts/build-shortcuts.mjs 重新生成 shortcuts/*.plist（加 --sign <文件夹> 顺便签好）
pnpm guide        # 由 shortcuts/使用说明.md 重新生成 shortcuts/使用说明.html
cargo test --manifest-path src-tauri/Cargo.toml   # Rust 测试
```

## 知识库在哪里

桌面 App 和 `pnpm dev:kb` 按这个顺序找知识库：

1. 环境变量 `DISE_KB_PATH`；
2. （仅桌面 App）`~/Library/Application Support/com.gegej1.dise/config.json` 里的 `kbPath`，例如 `{ "kbPath": "/Users/你/Documents/阅读" }`；
3. 默认 `~/Desktop/GHJProject/阅读`。

`pnpm dev:kb` 只读：中间件只提供 `GET /__kb/list` 和 `GET /__kb/read?path=`，只接受本机请求，并且只在开发服务器里存在，不会进入任何构建产物。

同一个 `config.json` 里还有 AI 运行的设置（见下文「入库和落裁决」），也可以用 `captureShortcut` 换掉记一笔的全局快捷键，写法如 `"Ctrl+Alt+K"`、`"Cmd+Shift+Space"`，必须带 ⌃、⌥ 或 ⌘ 之一。默认是 ⌃⌥N（⌘⇧N 已经是 Finder 的「新建文件夹」和 Chrome 的「新的无痕窗口」）。快捷键注册不上（被别的 App 占用，或者写法不对）时 App 照常运行，日志里写明原因，菜单栏和今日页也会提示。这些都可以在 App 的「设置」里改（见下文）。

想在一份知识库副本上试用 App、又不碰真正的设置时，可以用环境变量 `DISE_APP_DIR` 指定另一个文件夹放 `config.json` 和运行记录，用 `DISE_BRIDGE_DIR` 让 iPhone 互通用另一个文件夹（不碰真正的 iCloud）。试用的 App 还要换一个标识符，否则它会把命令行参数交给正在运行的那个 App，例如 `pnpm tauri build --config '{"identifier":"com.gegej1.dise.dev","productName":"底色测试"}'`。

## 设置（桌面 App）

左侧栏最下面的「设置」：

- **AI 引擎**：Claude 或 Codex（显示在这台 Mac 上找到的程序）、模型（可以写别名，留空就跟随引擎自己的默认）、每次运行的花费上限（美元，只对 Claude 有效）、运行时限（分钟）。保存后下一次运行就用新的设置。
- **知识库**：现在的文件夹和同步到哪里（只显示远端的主机名，或者本机文件夹，不显示地址本身）。「更换…」打开选择文件夹的窗口；只有 git 仓库的根目录才能选，选好后 App 重新载入。运行进行中不能换。
- **记一笔的快捷键**：点「录新的快捷键」后按下组合键。macOS 自己的快捷键（如 ⌘Space、⌃Space、⌘⇧4）和只带一个修饰键、会挡住打字或 App 自己快捷键的组合会被拒绝并说明原因；新的快捷键立刻生效，注册不上（被别的 App 占用）时原来的照常可用。
- **iPhone**：通过 iCloud 云盘和 iPhone 互通，默认打开；显示文件夹在哪里、是不是在看着、最近一次收进了什么、快捷指令签好没有，可以在访达中打开文件夹。
- **开机时自动打开**：默认关闭，只有你打开它才会在登录时启动。
- 打开日志文件夹、运行记录文件夹，以及 App 的版本。

`config.json` 里和 iPhone 有关的键：`bridgeEnabled`（写 `false` 关掉）和 `bridgeDir`（换一个文件夹；默认是快捷指令的 iCloud 文件夹里的 `底色/`）。

保存时 `config.json` 原子写入（先写临时文件再改名），不认识的键原样保留；`config.json` 不是有效的 JSON 时拒绝保存，免得丢掉里面的内容。网页版和演示没有设置。

## 桌面 App 的行为

- **窗口**：点关闭按钮只是把窗口藏起来，App 仍在运行；点 Dock 图标再显示；⌘Q 或菜单栏的「退出」退出。再次打开 App 会切回已经在运行的那一个，不会开第二个。
- **菜单栏图标**：一枚单色的印章（模板图，跟随浅色和深色菜单栏）。菜单：记一笔（显示快捷键）/ 打开底色 / 一行状态（收件箱 N 条 · 待裁决 M 项 · 同步状态）/ 立即同步 / 退出。Dock 图标保留。
- **记一笔窗口**：560×300 的无边框小窗口，出现在鼠标所在屏幕的上三分之一处，总在最前，不进 Dock。点到别的 App 时，纸条上没写字就自动收起，写了字就留着。记下或收起后，焦点回到打开它之前的那个 App。这个窗口只能在 `inbox/` 里新建文件，不能读、列出或改写知识库里的任何文件。
- **命令行**：`"/Applications/底色.app/Contents/MacOS/dise" --capture "要记下的话"` 把一条随手记交给正在运行的 App（没有在运行时会启动它，记下后留在菜单栏，不打开主窗口），和在纸条上记下完全一样，结果写进日志。`--answer Q-004 "回答"` 回答一个待裁决的问题，和在问题页的回答纸条上交上完全一样（来源记为 mac）。`--sync` 立即同步一次，并看一眼 iPhone 有没有放东西进来。`--ingest` 发起入库，`--land-rulings` 发起落裁决，可以加 `--engine claude|codex` 和 `--model <名字>` 只在这一次换掉设置里的引擎和模型；每一步和最后的结果都写进日志，结果要你确认时也会写明。`--approve` 确认并提交正在等你确认的那次结果，和点「确认并提交」完全一样。
- **外部链接**：http / https 链接用默认浏览器打开（网页版在新标签页打开）。
- **命令行环境**：从 Finder 启动的 App 拿不到 shell 配置里的环境变量，所以 App 启动时在后台跑一次登录 shell（`$SHELL -ilc`，最多 10 秒），记下 `PATH`、代理等变量，之后启动的 `git` 等子进程都用这份环境。失败时退回到固定的 `PATH`（Homebrew、`~/.npm-global/bin` 等）加系统代理设置（`scutil --proxy`）。
- **日志**：`~/Library/Logs/com.gegej1.dise/dise.log`（满 2 MB 轮换，保留 3 份旧文件）。记录每个命令的名称、路径、结果和耗时（逐个读取文件只在 debug 级别，每次载入只留一行汇总），每次同步的结果，以及前端载入结果和未捕获的错误；不记录文件内容、随手记的文字、提交说明和环境变量的值。
- **一次只做一件事**：写入、记一笔和同步共用一把「知识库锁」。正在进行的操作结束前，写入最多等 45 秒、同步最多等 20 秒，然后明确报告「知识库正忙」，不会一直卡住。入库或落裁决进行中（以及结果等你处理时），写入和同步立刻得到「知识库正忙：正在入库」这样的回答，界面上盖章确认和勾选抽查也会停用并提示「正在入库，结束后再改」；记一笔照常工作，入库进行中回答和驳回也照常（`inbox/裁决/` 只在落裁决时要等），每条都单独提交，不会混进这次运行。
- **通知**：一次运行结束（或者没通过检查、等你处理）时如果主窗口不在最前面，App 发一条系统通知；点通知会打开主窗口和这次的结果。
- **事件**：后端向窗口发送 `kb-changed`（文件被写入、新建，同步时拉到了新内容，一次运行提交、丢弃了改动，或者在设置里换了知识库；主窗口据此重新载入）、`sync-status`（同步开始、结束，或写入后有新的待推送提交）、`run-status`（一次运行开始、进入下一阶段或结束）、`run-step`（运行中的每一步：读、写、改、查找哪个文件，AI 说的话，被拒绝的操作）、`run-show`（点了运行的通知）和 `bridge-ready`（iPhone 互通的文件夹准备好了，主窗口马上导出页面），以后的功能可以直接订阅。`kb-changed` 的原因里还有 `bridge`：从 iPhone 收进了一条。

## 同步

数据安全优先于新鲜。每次同步都拿着知识库锁，按这个顺序：

1. 不是仓库根目录、没有上游分支、HEAD 不在分支上，或者有没做完的 rebase / merge / cherry-pick / revert / bisect 时，直接跳过并说明原因。
2. `git fetch` 上游分支，最多 30 秒（另有低速限制）；失败就是「离线」，什么都不改。
3. 只落后：`git merge --ff-only`；如果 git 说会覆盖本地文件，就报告「需要处理」，什么都不改。
4. 分叉：有已跟踪文件改动（含已暂存）时跳过；否则先把 HEAD 存到 `refs/dise/backup/<秒数>`，再 `git rebase`；任何失败都 `git rebase --abort`，确认 HEAD 回到备份那一刻，报告冲突的文件。
5. 领先：`git push <远端> HEAD:<上游分支>`，最多 30 秒；如果远端在这期间有了新提交，再从第 2 步来一次。
6. 备份只保留最新 10 个。

绝不 force push、`reset --hard`、stash、clean、checkout 或 restore 文件，也不碰未跟踪的文件。所有 git 调用都用明确的参数、不经过 shell、使用登录 shell 的环境，并且设置 `GIT_TERMINAL_PROMPT=0`。

什么时候同步：启动后（登录 shell 环境准备好之后）一次；每次写入或记一笔后约 3 秒（连续写入只同步一次）；每 10 分钟一次；主窗口获得焦点时（最多每分钟一次）；菜单栏的「立即同步」、点左侧栏的同步状态，或命令行 `--sync`。同步拉到新内容后，主窗口会重新载入。

## iPhone

手机在大陆没有 VPN，连不上 GitHub，也装不了 Obsidian。所以 iPhone 和 Mac 只通过 iCloud 云盘里的一个文件夹见面，手机上只用「快捷指令」和「文件」。

**文件夹**：默认是快捷指令 App 的 iCloud 文件夹里的 `底色/`（`~/Library/Mobile Documents/iCloud~is~workflow~my~workflows/Documents/底色/`，「文件」App 里是 iCloud 云盘 › 快捷指令 › 底色），快捷指令不用选文件夹就能读写这里。App 不会自己建 iCloud 的容器：这台 Mac 上还没有快捷指令的 iCloud 文件夹时，设置里会说明原因。

```text
底色/
  收件/记一笔/   手机 → Mac：随手记，一条一个 .txt
  收件/回答/     手机 → Mac：回答，文件名用编号开头（Q-001-….txt）
  阅读/          Mac → 手机：导出的底色层
  快捷指令/      三个快捷指令和使用说明
```

**收进来**（`src-tauri/src/bridge/import.rs`）：启动时、`收件/` 里有新文件时（FSEvents）、每 30 秒、主窗口获得焦点时和 `--sync` 时看一眼。只收 `.txt` 和 `.md`；iCloud 还没下载下来的占位文件（`.名字.txt.icloud`，别的类型的占位文件不管）先请 `brctl download` 下载，最近几秒还在变的文件过几秒再看，同一个文件最多这样快看 5 次，之后跟着 30 秒的节奏。随手记的时间取文件本身的时间（创建和修改时间里较早的那个，不可能的年份不用），文件名只用来区分文件。`记一笔/` 里的文件原样成为一条来源 `iphone` 的随手记；`回答/` 里 `Q-001-…` 的文件成为 `inbox/裁决/` 里对 Q-001 的回答。编号不存在、已经裁决或文件名里没有编号时，回答作为随手记收下，第一行写明原本是给哪个问题的，日志里也记一笔。都和 Mac 上记的完全一样地提交（同样的 YAML、同样的提交说明），拿知识库锁：记一笔什么时候都能收，落裁决进行中回答要等它结束。提交成功之后才删掉 iCloud 里的文件。每收一个，先在 App 的文件夹里（`iphone-imported.json`）记下它的哈希和要成为的路径（“进行中”），再提交，再记成“已收”；记不下来就整轮都不收，日志和「设置 › iPhone」里会说。所以删不掉的文件、提交后 App 正好退出的文件都不会被收两次：“进行中”的、记录坏掉重来的，都先在知识库的 git 历史和工作区里找同样内容的随手记或回答，找到就只删手机上的文件（只建了文件还没提交的，补上提交）。记录读不出来（权限、磁盘忙）时不动它，这一轮不收；内容坏掉时改名为 `.broken` 留着。收完照常在约 3 秒后同步。

**放出去**（`src/export/`、`src-tauri/src/bridge/export.rs`）：主窗口每次载入知识库（启动、`kb-changed`）后约 1.5 秒、以及每天零点过后，从知识库里只挑出 `self/底色.md`、`self/判例/`、`self/待裁决/` 和 `reports/`，其余文件在解析之前就丢掉，生成：

- `今日.html`（日期、今日一条、计数、链接）、`底色.html`（全部条目，草稿和 ✅ 看得出来）、`判例.html`、`待裁决.html`（每个问题的材料和要你定的事，以及在手机上怎么回答）、`待抽查.html`、`最近入库.html`（标题、结果一行，以及「待你抽查」「交给你裁决」「给已有待裁决补的材料」这几节；其余部分只在 Mac 上看，连节名也不带过去）；
- 给快捷指令的 `今日一条.txt`、`待裁决列表.txt`（一行一个 `Q-001｜标题`）和 `待裁决/Q-001.txt`（问题和 AI 建议，简短）。

页面只用内联 CSS，没有脚本（还带一条不许加载任何东西的 CSP），先照手机宽度排，跟随浅色和深色；页面之间用相对链接，指向没导出的页面的双链只显示文字。Rust 一侧只接受这些文件名，原子写入、内容没变就不写，删掉不再对应任何东西的旧文件，`阅读/` 以外什么都不碰。测试（`src/export/phoneExport.test.ts`）在 `raw/`、`wiki/`、`systems/`、`inbox/`、`index.md`、`log.md`、`self/` 的其他文件和报告的其余几节里放了特殊的记号，确认导出的每个字节里都没有它们，并且用全部文件和只用允许的文件导出的结果完全相同。

**快捷指令**：三个快捷指令的源文件在 `shortcuts/*.plist`，由 `scripts/build-shortcuts.mjs` 生成（`pnpm shortcuts`；测试检查它们是最新的、变量都指向前面的动作、只读写 `底色/` 里的路径）。App 把它们嵌在程序里，在这台 Mac 上用 `plutil` 和 `shortcuts sign --mode anyone` 签好，放进 `快捷指令/`，旁边是 `使用说明.html`。源文件变了或者签好的文件不见了才重签；签不了时设置里会说，说明里有手动建的步骤。说明的原文是 `shortcuts/使用说明.md`，`pnpm guide` 由它生成 HTML，下面这一段和它一字不差（测试会检查）。

还没在 iPhone 上验证过的：签好的快捷指令能否顺利导入、每个动作的参数在当前 iOS 上是否和生成的一致（尤其是「获取文件」的路径写法和「如果没有输入」的设置）、Quick Look 里页面之间的链接能不能点。导入不了时照下面的步骤手动建。

### 这是什么

iPhone 和 Mac 只通过 iCloud 云盘见面，手机上不用 VPN、不用 GitHub、不用装别的 App，只用自带的「快捷指令」和「文件」。

- 手机上记的一笔、对待裁决的回答，存成文本文件放进 iCloud；Mac 上的底色看到后收进知识库，提交成功后再把 iCloud 里的文件删掉。
- Mac 上的底色把「底色层」（底色、判例、待裁决、待抽查、最近一次入库）做成适合手机看的页面，放进 iCloud 给手机读。原料、知识页、体系、收件箱和日志都不会离开 Mac。

文件夹在「文件」App 里：iCloud 云盘 › 快捷指令 › 底色。

- `收件/记一笔/`：手机写给 Mac 的随手记
- `收件/回答/`：手机写给 Mac 的回答
- `阅读/`：Mac 放给手机看的页面和文字
- `快捷指令/`：三个快捷指令和这份说明

Mac 上的底色要开着（菜单栏里有它就行），手机上记的东西一般在 iCloud 同步过来后半分钟内收进知识库。

### 装上三个快捷指令

1. 在 iPhone 上打开「文件」App，进入 iCloud 云盘 › 快捷指令 › 底色 › 快捷指令。
2. 依次点「记一笔」「看底色」「答裁决」三个文件，在弹出的页面里点「添加快捷指令」。
3. 第一次运行时，快捷指令会问能不能访问文件，选「允许」。

想更快：在主屏幕上长按空白处添加「快捷指令」小组件，或者在「设置 › 操作按钮」里把「记一笔」设成操作按钮。

如果这三个文件打不开或者没有出现，可以照下面「手动建」的步骤自己建，每个只要几步。

### 怎么用

- **记一笔**：在任何 App 里选中文字或网页，点「共享」，选「记一笔」；或者直接运行它，打字或按键盘上的麦克风说话。看到「已记下」就好了。
- **看底色**：运行后选「今日一条」直接看今天的一条；选「整张底色」「待裁决」「待抽查」「判例」「最近入库」打开对应的页面。
- **答裁决**：运行后从列表里选一个问题，先看问题和 AI 的建议，再打字或说出你的回答。回答会原样交给 Mac 上的底色，进裁决收件箱，等下次落裁决。

也可以在「文件」App 里直接点开 `阅读/` 里的页面。有些预览里点页面之间的链接没反应，这时回到文件夹里点另一个页面就行。

### 手动建「记一笔」

1. 打开「快捷指令」，点右上角「＋」，名字写「记一笔」。
2. 点底部的「ⓘ」，打开「在共享表单中显示」；把「如果没有输入」设成「请求输入」，类型选「文本」。
3. 添加「从输入中获取文本」，输入选「快捷指令输入」。
4. 添加「格式化日期」：日期选「当前日期」，格式选「自定义」，格式字符串填 `yyyy-MM-dd'T'HH-mm-ss`。
5. 添加「设定名称」：把上一步得到的「文本」的名称设为「格式化的日期」后面接着打 `.txt`。
6. 添加「存储文件」：关掉「询问存储位置」，路径填 `/底色/收件/记一笔/`，关掉「覆盖」。
7. 添加「显示结果」，写「已记下」。

### 手动建「看底色」

1. 新建快捷指令「看底色」，添加「从菜单中选取」，选项写：今日一条、整张底色、待裁决、待抽查。
2. 「今日一条」下面：添加「获取文件」，关掉「显示文稿选择器」，路径填 `底色/阅读/今日一条.txt`；再添加「显示结果」。
3. 「整张底色」下面：添加「获取文件」，关掉「显示文稿选择器」，路径填 `底色/阅读/底色.html`；再添加「快速查看」。
4. 「待裁决」「待抽查」照第 3 步，路径分别是 `底色/阅读/待裁决.html` 和 `底色/阅读/待抽查.html`。

### 手动建「答裁决」

1. 新建快捷指令「答裁决」，添加「获取文件」，关掉「显示文稿选择器」，路径填 `底色/阅读/待裁决列表.txt`。
2. 添加「拆分文本」，按「换行符」拆分。
3. 添加「从列表中选取」，提示写「回答哪一个？」。
4. 添加「匹配文本」，正则写 `Q-[0-9]+`，文本选「所选项目」。
5. 添加「从列表中获取项目」，取「第一项」。这就是问题的编号。
6. 添加「获取文件」，关掉「显示文稿选择器」，路径填 `底色/阅读/待裁决/`，接着插入上一步的「列表中的项目」，再打 `.txt`；然后添加「显示结果」。
7. 添加「请求输入」，类型「文本」，提示写「你怎么定？」。
8. 添加「格式化日期」，和「记一笔」第 4 步一样。
9. 添加「设定名称」：把「提供的输入」的名称设为编号（「列表中的项目」）、一个 `-`、「格式化的日期」，最后打 `.txt`。文件名一定要用编号开头，比如 `Q-001-2026-10-12T09-30-00.txt`。
10. 添加「存储文件」：关掉「询问存储位置」，路径填 `/底色/收件/回答/`，关掉「覆盖」。
11. 添加「显示结果」，写「已交上」。

### 要知道的

- 回答的文件名里没有编号，或者那个问题已经裁决了、不存在，回答不会丢：它会作为一条随手记收进收件箱，第一行写明原本是给哪个问题的。
- 手机上的文件只在 Mac 上提交成功后才删除；没删掉的也不会被收两次。
- 在「设置 › iPhone」里可以关掉这个功能，也能看到文件夹的位置和最近一次收到了什么。

## 入库和落裁决

入库处理 `inbox/` 根目录下的随手记，落裁决处理 `inbox/裁决/` 下的回答。规则在知识库的 `AGENTS.md` 里（第二节入库、第三节落裁决、第九节由 App 发起的运行）；App 交给引擎的任务提示词在 `runners/`。

**一次运行的过程**：

1. 先同步一次，把别处记下的内容拿到本机。知识库不是仓库根目录、不在分支上、有改了没提交的已跟踪文件、没有 `AGENTS.md` 时不开始；队列是空的就根本不启动引擎（运行要花钱）。
2. 记下开始时的状态：当前提交、队列文件的内容、已经存在的未跟踪文件（它们属于你，什么时候都不会被提交、还原或删除）。
3. 引擎在知识库里工作，App 把每一步发给窗口，引擎的原始输出逐行存下来。可以随时停止；超过时限会被停止。
4. 引擎结束后（不管是做完、出错、被停止还是超时），App 列出这次运行改了哪些文件，交给主窗口里的检查程序（`src/domain/gate.ts`）核对：
   - 只改了 `raw/`、`wiki/`、`systems/`、`self/`、`reports/` 和 `index.md`、`log.md`；
   - `raw/` 里已有的文件只在末尾追加，没有删除或改名；
   - 每个队列文件的正文（去掉 YAML，统一换行，去掉首尾空白）都能在 `raw/` 里逐字找到；
   - 底色里带 ✅ 的条目一个字都没变，✅ 没有增加也没有减少（新条目也不能带着 ✅ 出现）；
   - 已有判例里"## 裁决"一节（你的原话）一个字都没变，已有判例也没有被删除或改名（新建判例不受限制）；
   - 没有新的断链；入库写了报告；落裁决把回答过的 Q 文件改成"已裁决"（驳回抽查时新建了 Q 文件）；
   - 引擎没有自己提交，也没有动过不在 Git 里的文件。
   最后那行 JSON 缺了或写错了只算提醒。Rust 一侧在提交前再查一遍其中最基本的两条（允许的目录、`raw/` 只增不改）。

   另有一类改动不算违规，但要你确认（`AGENTS.md` 第九节"需要我确认的改动"）：底色里已有条目的任何改动（标题或正文，盖没盖章都一样）、没标「（草稿，待你确认）」的新条目、底色的 frontmatter、分节标题和前言，以及 `systems/` 里的任何新建、修改或删除。新加的草稿条目不用确认。`systems/` 这一条 Rust 一侧也会再查一遍。
5. 检查通过、引擎也正常结束：删掉内容已经进了 `raw/` 的队列文件，把检查认可的文件做成一次提交，然后同步。
6. **需要你确认**：没有违规、只有上面那类改动时，运行停下来，面板逐条列出它们和改动前后的对照。点「确认并提交」按正常方式提交（提交说明和平常一样，运行记录里写 `decision: "approved"`，历史里显示「已确认提交」）；也可以「丢弃（可找回）」。从命令行发起的运行会在日志里写明在等你确认；`dise --approve` 和点「确认并提交」一样。既有违规又有要确认的改动时，按没通过处理，要确认的那几项也一起列出来。
7. **没能提交**：检查通过了，但 git 拒绝了提交（比如钩子不让提交）。改动原样留着，面板写明 git 的错误，可以「重试提交」或丢弃；这不算检查没通过。
8. 没通过：改动原样留在知识库里，同步不会推送它们，由你决定——**丢弃**（先把这次改过的每个文件复制到运行记录里，再把已跟踪的文件还原、删掉这次新建的文件；引擎自己做了提交的话，再加一个撤回的提交，不改写历史）、**保留**（明知没通过也提交，记在运行记录里），或者手动改好后**重新检查**。App 在这期间退出的话，下次启动时会接着等你处理。

**引擎**：

- **Claude Code** 以受限模式运行：`claude -p … --restricted`，只有读、写、改、查找文件的工具，没有命令执行，不加载你的用户设置、项目设置、hooks 和 MCP 服务器，有花费上限；读写只限于知识库文件夹。登录用的 `apiKeyHelper` 和 `ANTHROPIC_*`、`CLAUDE_CODE_*`、`API_TIMEOUT_MS` 设置从 `~/.claude/settings.json` 复制进一个只有你能读的临时文件（权限 0600），只在引擎运行期间存在，内容从不写进日志。没有可用的登录时会明确报告「没有可用的登录凭据」。
- **Codex** 在自己的 `workspace-write` 沙箱里运行，不需要确认，关掉你配置里的插件、apps、hooks、MCP 服务器等。Codex 只能通过命令读文件，所以任务提示词后面会加一段说明：允许只读命令和 apply_patch，git、删除、移动仍然不许。

**设置**（`config.json`，和 `kbPath` 放在一起，每次运行时重新读取；也可以在 App 的「设置」里改）：

| 键 | 含义 | 默认 |
|---|---|---|
| `engine` | `"claude"` 或 `"codex"` | `claude` |
| `model` | 模型名或别名（只用于 `engine` 指定的引擎） | 引擎自己的默认 |
| `budgetUsd` | 一次 Claude 运行的花费上限（美元） | `10` |
| `runTimeoutMinutes` | 超过这么多分钟就停止引擎 | `30` |
| `claudePath`、`codexPath` | 不用 `PATH` 上的 `claude` / `codex`，改用这个程序 | – |

**运行记录**：每次运行一个文件夹，在 `~/Library/Application Support/com.gegej1.dise/runs/<时间>-<任务>/`：`run.json`（谁发起的、引擎、模型、花费、轮数、检查结果、怎么结束的）、`events.jsonl`（引擎的原始输出）、`steps.jsonl`（运行面板显示过的每一步）、`snapshot.json`（开始时的状态）、`beside.jsonl`（运行期间记下的随手记的提交，记下的那一刻就写进去，重启后也认得它们是你的）、丢弃时的文件副本。提交之前先把提交说明写进 `run.json`，App 正好在提交之后退出的话，下次启动能认出这个提交。丢弃要么全部做完，要么什么都不变。保留最新 20 次（还在等你处理的不删）。运行面板的「运行记录」列出它们（时间、任务、引擎、模型、结果、花费或 token 数、用时），点开一次能看到它的每一步和检查结果。这些文件含有知识库内容，只留在本机。

## 路径安全

前端传来的路径都要过同一套规则（Rust：`src-tauri/src/kb/paths.rs`，TypeScript：`src/store/kbPath.ts`）：只接受知识库内的相对 POSIX 路径；拒绝绝对路径、`.` / `..` 段、`.git/` 和其他隐藏目录、非 `.md` 文件；符号链接解析后必须仍在知识库内。改写是原子的（临时文件 + 重命名），新建也是（临时文件 + 硬链接，名字已被占用时失败而不是覆盖；提交失败时撤回新文件）。提交只包含这一个文件。
